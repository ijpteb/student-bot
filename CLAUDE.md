# CLAUDE.md — устройство проекта и принятые решения

Владелец проекта — не программист. Объяснять простым русским языком, ручные действия —
пошаговыми инструкциями. Работать этапами, после каждого этапа: тесты, инструкция
«как проверить в Telegram», коммит, ждать «ок». Ничего не выдумывать про системы вузов.
Предупреждать заранее обо всём платном.

## Этапы

1. ✅ Вопросы, исследование ЭИОС ИМЭС (см. `docs/research-imes.md`), план.
2. ✅ Каркас, база, ручной режим, домашние задания, напоминания, сводка, настройки.
3. Интерфейс коннектора, коннектор Moodle (ИМЭС — его настройка): вход, расписание, баллы.
4. Регулярная синхронизация, уведомления об изменениях расписания и новых баллах.
5. Согласие, /privacy, черновики политики и согласия (проверить юристу), проверка безопасности.
6. Сервер 24/7 в России (сначала проверить доступ к Bot API с него).
7. Закрытый тест (владелец, друг из ИМЭС, знакомые). Публичный запуск — только после.

## Ответы владельца (этап 1)

- Компьютер: **macOS**. Инструкции — для Mac; запуск двойным щелчком по `.command`.
- Хостинг: хочет бесплатно «на GitHub, как сайт gsw-portal». **Бот на GitHub не размещаем**
  (см. «Хостинг»). Код хранится на GitHub бесплатно; тесты гоняет GitHub Actions.
- Расписание в ручном режиме — «максимально точное»: чётность недель, разовые пары,
  отмены на день, сроки действия пары.
- Баллы в ручном режиме не вносятся.
- Друг из ИМЭС согласен: пароль один раз проходит через чат (сообщение сразу удаляется),
  храним только токен; согласен на обезличенные примеры ответов ИМЭС для тестов.
- Частота опроса вуза: расписание раз в 3 часа с 7:00 до 23:00 МСК, оценки раз в 6 часов.
- Оператор персональных данных — **физлицо** (владелец).

## Архитектура

```
bot/core/        ядро: не знает про Telegram (расписание, задания, напоминания, тексты)
bot/models.py    таблицы (SQLAlchemy 2)
bot/scheduler.py фоновый цикл: напоминания и сводки, раз в 30 секунд
bot/messenger.py интерфейс Notifier — как ядро отправляет сообщения
bot/telegram/    слой Telegram (aiogram 3): кнопки, диалоги, Notifier для Telegram
migrations/      Alembic
```

- Ядро возвращает тексты с простой разметкой `<b>`, `<i>` и ничего не знает о Telegram.
  Другой мессенджер = новый пакет рядом с `bot/telegram/` + свой Notifier.
- `users.platform` + `users.external_id` — пользователь привязан к мессенджеру, не к Telegram.
- Вложения хранятся у мессенджера (`file_id`), у нас только номер и `platform`.
- Адрес Bot API — `TELEGRAM_API_URL`, прокси — `TELEGRAM_PROXY` (в `.env`).

## Время и напоминания

- События (создано, отправлено, `fire_at`) — в UTC (`UTCDateTime`).
- Срок сдачи (`due_date`, `due_time`) и время пар — местные, «как у студента».
- Напоминание хранит и `local_at` (как ввёл студент), и `fire_at` (UTC). При смене
  часового пояса `fire_at` пересчитывается (`reminders.recompute_for_user`).
- Планировщик берёт из базы напоминания с `fire_at <= сейчас` и `sent_at IS NULL`,
  после отправки ставит `sent_at`. Поэтому перезапуск ничего не теряет; пропущенное во время
  простоя приходит сразу после запуска. Сбой связи — до 5 попыток, потом сообщение владельцу.
- Одно напоминание на задание (новое заменяет старое).
- Сводка: если `local_now >= digest_time` и сегодня ещё не отправляли, но не позже 3 часов
  после времени сводки. Нет невыполненных заданий — не отправляется (но день помечается).
- Чётность недели: `users.week1_start` — понедельник первой (нечётной) недели; по умолчанию
  неделя с 1 сентября текущего учебного года. Студент меняет в настройках (весенний семестр и т.п.).

## Безопасность и данные

- Каждый запрос к данным студента фильтруется по `user_id` (тесты `test_isolation*`,
  `test_cannot_open_foreign_homework`).
- `/delete_me` удаляет всё; заявки на вузы остаются как обезличенный счётчик (`user_id = NULL`).
- Секреты только в `.env` (в `.gitignore`). Журнал: тексты студентов не пишутся, токены и
  `password=`/`token=` вырезаются (`bot/logging_setup.py`).
- Служебные команды (`/stats`) — только `ADMIN_ID`; для остальных их как будто нет.
- Бот работает только в личных чатах.

## Технические решения

- Python 3.13, aiogram 3.31, SQLAlchemy 2.1, Alembic 1.20, asyncpg, PostgreSQL 17 (Docker).
- Без Redis: состояние диалогов в памяти — после перезапуска начатый ввод надо повторить,
  данные и напоминания в базе не страдают.
- Без отдельной библиотеки планировщика: цикл, читающий базу, проще и переживает перезапуски.
- **В данных кнопок (callback_data) нельзя двоеточие** — время кодируется как `HHMM`/`%Y%m%d%H%M`.
- Обработчики-роутеры aiogram модульные; `create_dispatcher` отцепляет их от старого
  диспетчера (нужно для тестов).
- Миграции: `alembic revision --autogenerate -m "..."` при `DATABASE_URL` на PostgreSQL;
  в шаблоне миграций есть `import bot.models` (нужен для типа `UTCDateTime`).
- Тесты: SQLite в памяти по умолчанию, `TEST_DATABASE_URL` — на PostgreSQL.
  `tests/test_telegram_flow.py` гоняет настоящие обработчики через поддельный сервер Telegram.

## Хостинг (решение этапа 6, предварительно)

Разместить бота бесплатно на GitHub, как сайт gsw-portal, **нельзя**:
- GitHub Pages отдаёт только готовые страницы, программу там не запустить.
- GitHub Actions — задачи до 6 часов с паузами между ними; база данных там не хранится.
- Главное: 152-ФЗ (ч. 5 ст. 18) требует хранить базу с данными граждан РФ на серверах в России,
  а серверы GitHub — за рубежом. Владелец сам поставил требование «база в России».
- Логи Actions в публичном репозитории видны всем.

Варианты: на время разработки и закрытого теста — Mac владельца (бесплатно, но только пока
Mac не спит); для 24/7 — сервер в России. Бесплатный уровень Cloud.ru Evolution упоминается
в обзорах, но условия (публичный IP, «только для тестирования») не проверены — проверить
на этапе 6. Иначе — недорогой VPS, цену назвать заранее.

## ИМЭС (кратко; подробно — docs/research-imes.md)

- `eos.imes.su` — Moodle 4.5 (сборка «СЭО 3KL», тема opentechnology).
- Веб-сервисы и мобильный сервис **включены**; `login/token.php` отвечает.
- Вход через браузер (`launch.php`) и QR **выключены** → путь только «логин+пароль → token.php».
  Пароль не храним: используем один раз, сообщение удаляем.
- Расписание — курс `course/view.php?id=54` («Расписание»); журнал и зачётка, вероятно, в
  модуле «Деканат» (`blocks/dof`). Доступность через API **не проверена** — первым делом
  этапа 3 диагностика на токене друга (список функций API без личных данных).
- Публичный режим подключения аккаунтов — только после решения вопросов с правилами вуза и 152-ФЗ.
